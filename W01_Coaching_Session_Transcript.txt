COACH:
Thanks, Tracy. Let's start with Express routing. In your own words, what is Express routing, and why is it useful in a server-side application?

STUDENT:
Express routing decides what code runs based on the URL and HTTP method. It is like a receptionist directing a visitor to the right place. Without routing, Node would give the same response instead of different pages.

I used three routes:

app.get('/', (req, res) => res.render('home'));
app.get('/organizations', (req, res) => res.render('organizations'));
app.get('/projects', (req, res) => res.render('projects'));

COACH:
Good explanation. Each route matches an HTTP method and path, then runs its handler. `req` represents the incoming request, `res` is the response object, and `res.render()` renders a view. Keeping routes separate makes the server's behavior easy to read and gives each page a clear URL.

STUDENT:
I chose three routes because it keeps the URLs and code clean, and each page can be handled independently.

COACH:
That makes sense. Separating routes supports readability and maintainability. What do you think would happen if you changed `app.get('/projects', ...)` to `app.post('/projects', ...)` but still tried to open `/projects` by typing it into your browser?

STUDENT:
The browser's address bar and navigation links normally send GET requests, so the route would not match and Express would likely show “Cannot GET /projects.” GET is for requesting a page, while POST is generally used to submit data.

COACH:
Exactly. The HTTP method is part of the route match, not just the path. Now let's move to JavaScript. Can you share a meaningful JavaScript function from your project and explain what it does?

Good explanation. In EJS, `<% %>` runs JavaScript without outputting it, `<%= %>` outputs escaped content, and `<%- %>` outputs unescaped content. STUDENT:

COACH:
Why did you choose CSS Grid with `auto-fit` and `minmax(220px, 1fr)` for your category list instead of using fixed-width columns or manually setting the number of columns for different screen sizes?

STUDENT:
`repeat(auto-fit, minmax(220px, 1fr))` makes the browser compute the column count from the container width, at every width, continuously—instead of me picking a handful of breakpoints and hoping the layout looks right in between.

Fixed-width columns such as `220px 220px 220px 220px` need roughly 950px including gaps. On a 600px phone, that can cause horizontal overflow. On a 1400px desktop, four 220px columns can leave a lot of empty space. I would need media queries to correct those problems.

COACH:
That's a strong explanation. `auto-fit` lets the browser fit as many columns as the available space permits, and `minmax(220px, 1fr)` sets a minimum column size while allowing columns to expand and share available space. One qualification: a 220px minimum can still overflow in a very narrow container, so a robust layout should account for that possibility.

COACH:
Your navigation CSS uses `:focus-visible` alongside `:hover`. Why is `:focus-visible` important for accessibility, especially for someone navigating your website using a keyboard instead of a mouse?

STUDENT:
A keyboard user has no cursor to tell them where they are—the focus indicator is their only “you are here” marker, so removing it makes the site unusable. `:focus-visible` lets the site show that indicator for keyboard users while sparing mouse users the persistent highlight that might tempt a developer to write `outline: none` and break accessibility for everyone.

In this project it is implemented as a 3px gold outline offset 2px from the element, meeting WCAG 2.4.7 and roughly the 3:1 contrast bar of WCAG 2.4.11, and the navigation specifically mirrors its `:hover` state so keyboard users see the same feedback mouse users do.

COACH:
Excellent explanation. You connected the CSS technique to the experience of someone using the website. Keyboard users need to identify which link or control currently has focus, and a visible focus indicator helps them do that. Matching `:focus-visible` with `:hover` also provides comparable feedback for keyboard and mouse users.

One standards clarification: WCAG 2.4.7, Focus Visible, is a Level AA criterion in WCAG 2.1. WCAG 2.4.11, Focus Not Obscured (Minimum), concerns whether focused content is hidden by author-created content; it is not the 3:1 focus-indicator contrast criterion. WCAG 2.2 criterion 2.4.13, Focus Appearance, addresses focus-indicator size and contrast at Level AAA.
